# 检索评测 · 使用说明

> 建于 2026-09-13。目标：把「检索好不好」从**定性判读**变成**可比的数字**。

## 为什么要有这个东西

项目此前的验收只有定性判据 —— `知识库测试题.md` 的 10 题人工判读 + 「D 组必须拒答」。
调参（换 embedding、改权重、开 rerank、调阈值）全靠感觉，改完没法说「比之前好多少」。

这个评测集补的是**检索层**的数字。分工要说清楚：

| 层 | 评什么 | 用什么 |
|---|---|---|
| 检索 | 该召回的条文有没有被召回、排第几、分数多高 | **本目录**（Recall@k / MRR / 阈值窗口） |
| 生成 | 答案对不对、有没有编、带不带条文号 | `..\知识库测试题.md`（人工判读 + D 组拒答） |

**它不判答案对不对。** 召回对了，LLM 仍可能读错表格格子 —— 那是生成层的事。

## 目录里有什么

| 文件 | 作用 |
|---|---|
| `评测集.jsonl` | **86 条**（77 正例 + 9 拒答负例），一行一条 |
| `build_evalset.py` | 评测集的**源码**（题目写在里面）+ 金标校验。要改题改这里，再跑一次 |
| `run_eval.py` | 跑分器。两种后端 × 12 组检索参数 |
| `config.example.json` | 复制成 `config.json` 填 Key（`config.json` 已 gitignore） |
| `结果_<后端>_<参数组>.md` / `.json` | 每次跑的产物 |

评测集条目结构：

```json
{"qid":"GB52-01","query":"半地下室是怎么定义的？","standard":"GB 50352-2019",
 "gold":["2.0.16"],"type":"keyword","difficulty":"easy","note":"超过净高1/3且不超过1/2"}
```

`gold` 是**金标条文号**，命中其中任意一条即算召回成功（部分题目允许两个等价的条文号）。
`build_evalset.py` 会校验每个金标都真实存在于 `chunks_v5` 里，写错条文号会直接报错退出。

## 三步走

### 第 0 步 · 拿 Key

知识库 → 右上角 **「服务 API」** → 建一个 Key。
知识库 ID 在知识库页面 URL 里 `/datasets/<这一段>`。

```bash
# 方式一：环境变量
set DIFY_API_KEY=dataset-xxxxxxxx
set DIFY_DATASET_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

# 方式二：在本目录建 config.json（照抄 config.example.json）
```

### 第 1 步 · 跑基线

```bash
python run_eval.py --backend dify --profile base
```

`base` = 混合检索 + rerank(`qwen3-rerank`) + TopK5 + 阈值0.5，即线上默认配置。

> ⏱ **86 条 × 6.5 秒 ≈ 9 分钟**。Dify Sandbox 免费版的知识库请求限制是 **10 次/分钟**，
> 所以默认限速 6.5s。付费版可以 `--delay 0` 加速。

### 第 2 步 · 扫参数，找最优配置

```bash
python run_eval.py --backend dify --all       # 12 组参数各跑一遍（约 100 分钟，可分批）
```

分批跑更实际：

```bash
python run_eval.py --backend dify --profile pure   # 纯向量，无 rerank
python run_eval.py --backend dify --profile w55    # 混合 + 加权 5:5
python run_eval.py --backend dify --profile no_rk  # 混合但不配 rerank
```

对比重点：

| 想问的问题 | 比哪两组 |
|---|---|
| rerank 到底有没有用？ | `pure` / `w55` vs `base` |
| 「加权打分」能不能替代 rerank 模型？ | `w55` vs `no_rk`（后者验证 Score 阈值是否失效） |
| 通义两支 rerank 哪个好？ | `base`(`qwen3-rerank`) vs `rk_gte`(`gte-rerank-v2`) |
| TopK 提到 10 有用吗？ | `base` vs `top10` |
| 语义 / 关键词各占多少权重最好？ | `w73` / `w55` / `w91` |

### 第 3 步 · A/B：本地 0.6B vs 云端 v4

两边都是「**纯向量、无 rerank、无阈值、TopK10**」，唯一变量就是 embedding 模型：

```bash
python run_eval.py --backend chroma --profile local    # 本地 Qwen3-Embedding-0.6B（首次载模型 ~7 分钟）
python run_eval.py --backend dify   --profile pure     # 云端通义 text-embedding-v4
```

→ 两份报告的 `Recall@10` / `MRR` 直接可比。这是你之前想做的对照实验，
用同一份评测集出数，结论才站得住。

## 结果怎么读

```bash
# 控制台末尾会直接打出
  Recall@1  82.0%
  Recall@3  91.5%
  Recall@5  94.0%
  MRR       0.872
  未命中    7 / 77
  负例最高分 0.412（超阈 2 / 9）
  正例金标 5% 分位 0.686 → 阈值窗口 (0.412, 0.686]，建议 0.55
```

| 指标 | 怎么用 |
|---|---|
| **Recall@1** | 最关键。LLM 通常只吃前 3~5 条，排第一的那条决定答案质量 |
| Recall@5 | 上限参考。到 5 条还没召回，基本就是切分或语料的问题了 |
| MRR | 排序质量。两个配置 Recall 一样时，MRR 高的更好 |
| 未命中明细 | 报告里逐条列出「哪些题没召回 + 实际返回了什么」，直接指向要修的地方 |
| 负例最高分 | 拒答的水位线 |

### 阈值该定在哪（报告会自动算）

报告里的「阈值定在哪」一节给出的是一个**窗口**：

```
负例最高分 0.412  ←→  正例金标分数 5% 分位 0.686
        → 窗口 (0.412, 0.686]，建议 0.55
```

- 阈值低于窗口下界 → 负例会漏进来（该拒答的答了）
- 阈值高于窗口上界 → 正例开始被误伤（该答的拒了）
- **如果窗口不存在**（正例分数不显著高于负例）→ 说明不能再靠调阈值了，
  得先换 rerank 模型或调权重。这种情况报告会直接说明。

## 已知局限（必读，写进答辩材料里反而是加分项）

1. **召回对 ≠ 答案对。** 表格类 6 条尤其如此 —— 数值都召回了，但「哪一格属于哪个房间」仍需推断（v5 已知的遗留问题）。这层要靠 `知识库测试题.md` 的人工判读兜。
2. **Dify hit-testing 单次最多返回 10 条**，`top_k > 10` 没有意义。
3. **拒答是整个链条最弱的一环。** 检索层只能保证「分数低」；真正拒答靠提示词 7 条铁律。所以负例超阈数 ≠ 会编造，最终仍要看 D 组。
4. **金标绑定 `chunks_v5` 现文本。** 一旦切分脚本改动、条文号变化，必须重跑 `build_evalset.py` 校验，否则金标会静默失效。
5. **负例偏「易」**：9 条都是「库里根本没有」的。真正难的是「库里相关但答案不同」—— 比如问Ⅰ区气候指标（库内只存了 1/3 项，另两项缺失）。这类题留在 `知识库测试题.md` 的 B3。
6. **query 长度上限 250 字符**（Dify hit-testing 硬限制），评测集已校验。

## 参数组速查

| profile | 检索方式 | rerank | TopK | 阈值 |
|---|---|---|---|---|
| `base` | hybrid | qwen3-rerank | 5 | 0.5 |
| `sem` | semantic | qwen3-rerank | 5 | 0.5 |
| `pure` | semantic | ✗ | 10 | ✗ |
| `kw` | full_text | ✗ | 10 | ✗ |
| `w73` / `w55` / `w91` | hybrid | 加权打分（关键词权重 0.3 / 0.5 / 0.1） | 10 | ✗ |
| `no_rk` | hybrid | ✗ | 5 | 0.5（**无效**，用来验证） |
| `rk_gte` | hybrid | gte-rerank-v2 | 5 | 0.5 |
| `top10` | hybrid | qwen3-rerank | 10 | 0.5 |
| `thr03` / `thr07` | hybrid | qwen3-rerank | 5 | 0.3 / 0.7 |
| `local` | 本地 Chroma 纯向量 | ✗ | 10 | ✗ |

其他常用参数：`--only-type table`（只跑某题型）、`--only-standard "JGJ 38-2015"`、
`--limit 20`（先小样本试跑）、`--top-k 8`（覆盖参数组的 TopK）、`--out-tag exp1`（区分多轮实验）。
