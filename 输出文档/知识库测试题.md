### A1.《民用建筑设计统一标准》里"半地下室"的定义是什么？

- **正确答案**：`GB 50352-2019` 第 **2.0.16** 条 —— 房间地平面低于室外地平面的高度**超过该房间净高的 1/3，且不超过 1/2** 者为半地下室。
- **库内原文**（逐字一致）：
  > 半地下室 semi-basement 房间地平面低于室外地平面的高度超过该房间净高的1/3，且不超过1/2者为半地下室。
- **易混淆**：**2.0.15** 是"地下室"—— 超过净高的 **1/2** 者。答反即错。
- **合格标准**：给出定义 + 条文号 2.0.16（项目硬要求：不带条文号即不合格）。

### A2.《建筑防火通用规范》对消防救援口有哪些要求？

- **正确答案**：`GB 55037-2022` 第 **2.2.3** 条（全文强制），**共 5 款**：
  1. 沿外墙的每个防火分区在对应消防救援操作面范围内设置的消防救援口不应少于 **2 个**；
  2. 无外窗的建筑应**每层**设置；有外窗的建筑应**自第三层起**每层设置；
  3. 净高度和净宽度均不应小于 **1.0m**，当利用门时净宽度不应小于 **0.8m**；
  4. 应易于从室内和室外**打开或破拆**，采用玻璃窗时应选用**安全玻璃**；
  5. 应设置可在室内和室外识别的**永久性明显标志**。
- **前置句**：除有特殊要求的建筑和甲类厂房可不设置消防救援口外，在建筑的外墙上应设置便于消防救援人员出入的消防救援口。
- **⚠️ 上一版错在哪**：上一版写"共 4 款"，漏了第 5 款（永久性标志），且把第 4 款简化成"应易于从室内和室外打开"，丢了"或破拆、安全玻璃"。
- **合格标准**：5 款齐全，第 3 款的 1.0m / 0.8m 数字要对。
- **配套条文**：**6.5.8** —— 建筑外部装修和户外广告牌不应遮挡或减小消防救援口。

### A3.《图书馆建筑设计规范》里"基本书库"和"特藏书库"分别指什么？

- **正确答案**：`JGJ 38-2015`
  - 第 **2.0.6** 条 —— 基本书库 basic stack rooms：图书馆的主要藏书区，**又称基藏书库**。
  - 第 **2.0.7** 条 —— 特藏书库 special stacks：收藏**珍善本图书及重要的电子文献资料、音像资料**等，对保存条件有特殊要求的库房。
- **易混淆**：**2.0.8** 是"珍善本书库"（特藏书库的**一种**，收藏国家或地方级珍贵文献，重安全防范）。别把 2.0.7 和 2.0.8 搞混。
- **合格标准**：两个定义不互换，中文术语保留（英译可省）。

## 修复记录（2026-09-13 已完成 → chunks_v5）

**根因**：切分脚本 `split_articles_v2.py` 的 `NOISE_RE` 含 `\d{1,3}` 分支 —— 「整行是 1~3 位纯数字」被无条件
当噪声丢弃。本意是清页脚页码，但它连表格数值、条文枚举序号一起删了。

```python
# 修复前
NOISE_RE = re.compile(
    r"^\s*(?:[-—=*_·]{3,}|住房城乡建设部信息公开.*|.*信息公开浏览专用.*|\d{1,3}"
    r"|•\s*\d{1,3}\s*[.．]?|X1)\s*$")           # ← \d{1,3} 是元凶

# 修复后：去掉该分支，裸数字行改由下面这条规则单独处理
BARE_NUM_RE = re.compile(r"^\s*\d{1,3}\s*$")
# 主循环里：只有「该页最后一个非空行」的裸数字才当页脚丢弃
if BARE_NUM_RE.match(s) and idx == last_idx:
    continue
```

**修复依据**：页脚页码总排在页面内容末尾，表格数值在页面中部。实测校验 ——
丢弃 176 行**全部**是印刷页码序列（GB 50352 从 4/5/6/8/9/10…61，JGJ 38 从 3/4/5…61），
保留 223 行**全部**是表格数值或条文枚举序号，**零误伤**。

**修复效果**（v4 → v5，1083 条键完全一致，仅 16 条内容变化）：

| 找回内容 | 示例 |
|---|---|
| 表格数值 | GB 50352 表 3.2.1 → `1类5年 / 2类25年 / 3类50年 / 4类100年`；JGJ 38 表 8.2.1-1 → `20/18/16/14`；表 7.2.1 → `3/450/2/300/1/150` |
| **条文枚举序号** | GB 50352 8.4.8 补回 `2 3 4`（原为 `1…；应通风良好…；与其他毗邻房间…；室温…；5 …`，序号缺失读起来像病句）；GB 55031 3.1.6 补回 `3 4 5` |

> 枚举序号的丢失此前一直没被发现 —— 结构校验只查条文号连续性，不查**条文内部**的枚举序号。

**仍未解决**：表格是「数值全但行列扁平」的流文本，数值与行名的对应仍需推断。彻底解决需表格结构化
